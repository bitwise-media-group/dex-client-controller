Application teams declare the OAuth2 clients and identity providers they need as namespaced DexClient and DexConnector resources. The controller registers them in a running dex through its gRPC API, over mutual TLS — secrets stay in Kubernetes Secrets, and dex's config file is never touched.

$ kubectl get dex -A

// WHY NOT REWRITE THE CONFIG FILE

dex already ships an API for this. The controller drives it from outside, so dex stays untouched.

No restarts

Clients and connectors are created and updated live through dex's gRPC API. A changed connector bumps its resource version, and dex rebuilds it on next use.

Secrets stay Secrets

Reference an existing Secret with secretRef, or let the controller generate one it owns. Secret contents are never cached, and rotating one rotates the client in dex.

GitOps-friendly

Each team's resources live in its own namespace and repository. IDs default to <namespace>-<name>, so namespaces cannot collide.

Additive, any backend

Works on every dex storage backend. staticClients and staticConnectors keep working: a resource claiming a static ID reports ReadOnly and never touches it.

Oldest claim wins

When two resources claim one ID, the oldest owns it and the rest report Conflict. Delete the owner and the next claimant takes the dex entry over in place.

Drift repaired

dex has no change events, so every resource is re-reconciled on --resync-period. A dex on memory storage that restarts is repopulated within one period.

01

Open dex's API

Enable dex's gRPC API with tlsClientCA and issue the controller a client certificate; set DEX_API_CONNECTORS_CRUD=true to manage connectors too.

Install guide
$ kubectl apply -f dex-client-controller-dex-tls.yaml
02

Install the chart

Point the controller at dex's gRPC address and a Secret holding its client certificate.

Helm values
$ helm install dex-client-controller oci://ghcr.io/bitwise-media-group/dex-client-controller/charts/dex-client-controller --namespace dex-client-controller --create-namespace --set dex.address=dex.dex.svc.cluster.local:5557
